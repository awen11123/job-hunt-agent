# Windows 使用指南

本指南面向直接使用安装包的用户，不要求安装 Codex、Python、Node.js，也不要求购买或配置任何大模型 API。

## 下载安装

1. 打开项目的 GitHub Releases 页面，下载最新的 `JobHuntAgent-Setup-<版本>.exe`。
2. 双击安装包，按提示完成安装。程序安装在当前 Windows 用户目录，不需要管理员权限。
3. 桌面快捷方式默认不勾选；开始菜单始终会创建 `Job Hunt Agent` 入口。
4. 启动后，默认浏览器会打开本机工作台。地址以 `http://127.0.0.1:` 开头，数据没有因此上传到互联网。

安装包暂未进行商业代码签名。如果 Windows SmartScreen 显示“未知发布者”，请先确认文件来自本项目的 GitHub Release，并可对照同一 Release 中的 `.sha256` 文件核验下载完整性。

## 首次配置

进入“设置 > 本地数据”，填写以下三项：

- 投递 Excel：现有 `.xlsx` 文件的完整路径。可以在资源管理器中按住 Shift 右键文件，选择“复制文件地址”，再去掉最外层引号。
- 备份目录：每次写入 Excel 前保存原文件副本的位置。默认目录可以直接使用。
- 面经目录：本地 Markdown 面经和索引的保存位置。默认目录可以直接使用。

保存后回到“投递看板”。如果 WPS 或 Excel 正在占用投递文件，请先关闭文件再确认写入；应用会停止本次修改，不会强行覆盖。

## 准备 Excel

应用直接使用 Excel 作为投递记录的唯一数据源。推荐把工作表命名为 `投递总览`；没有该名称时会读取第一个工作表。

第一行必须依次包含以下九列：

| 企业 | 投递岗位 | 投递日期 | 所在地 | 当前状态 | 下一节点 | 节点时间 | 岗位链接 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

没有旧表时，在 WPS 新建空白表格，填写这一行表头并保存为 `.xlsx` 即可。真实投递表不需要复制进程序目录，也不要上传到公开 GitHub 仓库。

## 模型服务是可选的

不配置模型时，投递看板、面经、复盘、搜索筛选和规则化写入仍然可用。需要更自由的自然语言理解时，再进入“设置 > 模型服务”选择：

- DeepSeek、通义千问、Moonshot 或 OpenAI 兼容接口：需要相应服务商的 API Key。
- Ollama：模型在本机运行，默认不需要 API Key。

API Key 只保存在 Windows 凭证管理器中，不会写入项目文件、Excel 或公开仓库。使用远程模型时，助手输入会发送给所选服务商；应用不会自动上传整份 Excel 或整个面经目录。

## Notion 是可选的

面经默认保存在本地。需要跨设备查看时，可以在“设置 > Notion 面经”配置 Integration Token 和数据库 ID，再从面经列表手动同步指定记录。详细步骤见 [Notion 配置](notion-setup.md)。

Notion 同步只发送用户主动选择的面经。投递 Excel 不会同步到 Notion。

## 备份恢复

每次确认 Excel 写操作前，应用会在备份目录生成一份修改前的 `.xlsx` 副本。需要恢复时：

1. 关闭 Job Hunt Agent，并关闭 WPS 或 Excel 中的投递表。
2. 在备份目录按修改时间找到最近一份正确副本。
3. 先保留当前文件，再用该副本替换投递 Excel。
4. 重新启动应用并确认看板内容。

## 升级与卸载

安装新版时直接运行新的安装包即可。相同应用会原位升级，现有 Excel、面经、备份、普通设置和 Windows 凭证不会进入安装目录，也不会被覆盖。

从 Windows“设置 > 应用”卸载 `Job Hunt Agent` 后，程序文件和快捷方式会被移除；外部 Excel 以及 `%APPDATA%\JobHuntAgent` 下的配置、面经和备份会保留。这样重装不会丢数据。若确定不再需要，可在备份确认后手动删除该数据目录。

## 启动故障

重复启动时，程序会打开已经运行的本机实例，不会启动第二套服务。若双击后没有打开页面，请先从任务管理器结束旧的 `JobHuntAgent.exe` 再重试。

启动阶段的诊断信息保存在 `%APPDATA%\JobHuntAgent\startup-error.log`。该日志只在本机生成，不包含在安装包或 GitHub 仓库中。
