# WPS 秋招投递表流程分区与配色设计

## 目标

在用户已经手工整理并补全岗位链接的 `秋招投递总览.xlsx` 上原位优化：保留全部文字、链接、合并关系与工作表结构，将结束流程稳定移动到底部，并以不同颜色区分流程节点。

## 已选方案

采用方案 A“阶段色 + 粗分界”：不插入空白行或分区标题行，避免干扰筛选和后续追加记录。进行中记录保持当前相对顺序；结束记录保持当前相对顺序并整体沉底；第一条结束记录上方增加粗分界线。

## 配色

- 已投递 / `applied`：蓝色。
- 笔试、测评完成：黄色。
- AI 面试完成：绿色。
- 测评异常、待人工处理：橙色。
- 简历未通过、结束、拒绝、放弃：红色状态格，整行使用浅灰弱化。
- 当前状态列使用主色，下一节点与节点时间使用同色系浅色，方便横向阅读。

## 内容保护

- 不重建工作簿，不从旧 JSON 或 Notion 重新导出。
- 不修改用户手工填写的公司、岗位、日期、地点、下一节点、时间、链接显示文本、备注。
- 超链接目标、批注、单元格样式和同行合并关系随记录移动。
- 仅将“示例出行”和“示例旅行”的当前状态改为“AI面试完成”；不虚构节点日期。
- 示例通信等同公司多岗位作为相邻组整体移动，并恢复原有合并单元格。

## 文件安全

- 修改前将原工作簿复制到项目内被 Git 忽略的 `backups/` 目录。
- 先保存到目标目录的临时文件，校验可重新打开后再原子替换主工作簿。
- 若 WPS 锁定文件，停止替换并保留原文件。
- 真实求职数据和私有链接不进入 Git；自动化测试只使用合成数据。

## 验收标准

- 示例出行、示例旅行显示为“AI面试完成”并使用绿色阶段色。
- 示例汽车、示例AI、示例制造等结束流程位于表格底部，进行中流程相对顺序不变。
- 第一条结束流程上方有明显粗分界线，结束行整体弱化。
- 示例平台“测评异常”仍属于进行中流程并使用橙色，不被误判为结束。
- 用户原有文字、岗位链接目标、合并单元格和筛选范围完整保留。
- 表头冻结为第 1 行，打开文件后可正常筛选和查看。
