# Notion 面经属性精简设计

## 目标

精简面试记录数据库页面顶部的属性区，同时保证旧属性中的唯一信息先进入七章正文，不因删除数据库属性而丢失。

## 最终属性

数据库只保留五个属性：

- `面试`：标题；
- `时间`：面试时间；
- `结果`：当前结果；
- `面试轮次`：轮次说明；
- `分析状态`：整理状态。

`分析状态` 中现有的英文值 `completed` 统一替换为中文 `已整理`。

删除以下八个旧属性：

- `Prompt 版本`；
- `关联投递`；
- `原始笔记`；
- `形式`；
- `总体复盘`；
- `模型版本`；
- `结构化面经`；
- `自评分`。

## 内容保全

删除属性前，对每个数据库页面分别处理：

1. 读取 `总体复盘` 和 `结构化面经` 的非空文本；
2. 将尚未出现在正文中的文本追加到固定章节“面试主线与整体评价”，使用三级标题区分“总体复盘”和“考察主线”；
3. 重新读取页面正文，逐字确认两段文本已经保存；
4. `原始笔记` 仅为“完整正文已保存”的元数据说明，不迁移到正文；
5. 只有所有非空唯一文本都通过保全校验后，才允许删除旧属性。

所有迁移均按页面独立执行，不为原本为空的属性编造内容。

## 执行顺序

1. 只读预检数据库页数、七章正文结构、旧属性及非空值数量；
2. 向对应页面的“面试主线与整体评价”章节追加需要保留的文本；
3. 回读并校验正文包含迁移文本；
4. 将页面状态更新为 `已整理`；
5. 删除八个旧数据库属性；
6. 再次读取数据库元数据和两份页面，确认只剩五个属性、状态均为 `已整理`、正文仍为七章结构。

若正文追加或校验失败，停止执行，不删除任何数据库属性。

## 隐私与范围

- 仓库只保存通用迁移规则和虚构测试数据；
- 公司名、面试正文、页面标题、Notion ID 和令牌只在运行时读取，不写入 Git；
- 不修改 WPS 投递表，也不修改 180 题页面；
- 不改动面试标题、时间、结果和轮次的现有值。

## 验收标准

- 面试记录数据库恰好保留五个约定属性；
- 两份面经的 `分析状态` 均为 `已整理`；
- 原有非空的总体复盘与结构化面经文本已出现在对应正文中；
- 两份正文仍各包含七个固定二级章节；
- 180 题页面区块数量保持不变；
- 操作日志和 Git 变更不包含任何私有内容或标识。
