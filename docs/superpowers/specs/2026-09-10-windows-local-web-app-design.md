# Windows 本地 Web 应用设计

## 目标

将现有 Job Hunt Agent 从面向 Codex/MCP 的开发者工具扩展为普通 Windows 用户可直接使用的本地应用。用户无需安装 Python、Node 或 Codex，即可管理投递记录、整理面经，并按需接入大模型和 Notion。

## 已确认的产品决策

- 使用 Windows 安装程序和桌面快捷方式，双击后自动打开本地网页。
- Excel 是投递记录的唯一数据源。
- Notion 是可选增强；未配置 Notion 时面经保存为本地私有 Markdown。
- 不要求任何模型 API Key；基础功能在无模型模式下可用。
- 模型层不绑定 GPT，支持 OpenAI 兼容接口和本地 Ollama。
- 主界面采用投递看板与可收起的侧边对话窗口。
- 所有写操作先生成预览，用户确认后才能执行。

## 用户体验

### 首次启动

1. 用户安装应用并从桌面快捷方式启动。
2. 应用仅在 `127.0.0.1` 启动本地服务，并自动打开默认浏览器。
3. 首次配置向导要求用户选择或新建 Excel 投递文件。
4. Notion、模型供应商和备份目录均为可选设置。
5. 配置完成后直接进入投递看板，不展示营销首页。

### 主界面

- `投递看板`：展示投递总数、进行中、待测评、待面试和已结束统计，以及可搜索、筛选的投递列表。
- `面经`：管理本地 Markdown 面经，并在配置 Notion 后展示同步状态。
- `复盘`：生成日复盘、周复盘、待办和流程漏斗。
- `设置`：配置 Excel 文件、备份目录、Notion、模型供应商和隐私选项。
- `侧边对话`：接受自然语言查询和操作请求，可收起，不遮挡主要看板。

### 对话操作协议

对话分为读取和写入两类：

- 读取操作直接执行，例如查询本周投递数、等待面试的岗位或最近面经。
- 写入操作只生成结构化操作草稿，例如新增投递、更新状态、保存面经或同步 Notion。
- 草稿必须展示变更前后值、目标数据源和可能发送给远程模型的内容类别。
- 用户可以确认、修改或取消草稿；只有确认后的草稿才能调用写入工具。
- 每次确认生成一次性确认令牌和幂等操作 ID，防止刷新、重试或双击造成重复写入。

## 系统架构

```text
Windows Installer / Desktop Shortcut
                 |
          Local App Launcher
                 |
     FastAPI on 127.0.0.1 only
        |        |         |
        |        |         +-- LLM Provider Adapters
        |        +------------ Interview Stores
        +--------------------- Excel Application Repository
                 |
       React + TypeScript UI
```

### 本地启动器

- 选择空闲本地端口，启动 FastAPI，并等待健康检查通过。
- 启动成功后打开默认浏览器。
- 防止同一用户重复启动多个写入进程；第二次启动只打开现有页面。
- 应用退出时正常停止服务并完成待处理备份。

### FastAPI 后端

- 暴露看板查询、操作草稿、确认执行、设置、健康检查和同步状态接口。
- 复用现有领域模型、应用服务、面经服务、报告服务和幂等逻辑。
- MCP 服务继续保留，Web API 与 MCP 共享同一服务层，不复制业务规则。
- API 只绑定本机回环地址，并使用启动时生成的会话令牌保护写接口。

### React 前端

- 使用 React、TypeScript 和 Vite 构建，产物作为静态资源打包进安装程序。
- 采用安静、紧凑的工作台布局，优先支持搜索、筛选、状态比较和重复操作。
- 使用标准图标按钮、工具提示、状态色和稳定列宽，避免营销式卡片堆叠。
- 写入预览是独立确认面板，不允许对话消息直接触发持久化。

## 数据设计

### Excel 投递仓库

- Excel 保存公司、岗位、投递日期、地点、当前状态、下一节点、节点时间、岗位链接和备注。
- 应用直接读取用户选择的 Excel 文件，不建立 SQLite 双写数据源。
- 写入前创建时间戳备份，写入临时文件，验证可重新打开后再原子替换。
- WPS 占用文件时停止写入并保留操作草稿，不生成部分更新。
- 保留用户已有样式、合并单元格、超链接、排序和结束流程分隔规则。

### 面经存储

- 未配置 Notion 时，每场面经保存为本地私有 Markdown 和小型索引文件。
- 配置 Notion 后，本地草稿先持久化，再创建或更新 Notion 页面。
- Notion 同步失败时保留本地草稿并标记为待同步；重试使用相同幂等 ID。
- 本地索引只保存必要元数据和 Notion 页面 ID，不缓存 Notion Token。
- Git 忽略本地面经、索引、备份、日志和所有用户数据目录。

## 模型适配

### 统一接口

建立 `LLMProvider` 协议，提供聊天和结构化输出能力。业务服务只依赖该协议，不依赖具体厂商 SDK。

首批适配器：

- DeepSeek 预设。
- 通义千问预设。
- Moonshot 预设。
- OpenAI 兼容自定义地址。
- Ollama 本地接口，无需 API Key。

### 无模型模式

- 看板、表单、筛选、状态更新、备份、Notion 同步和报告模板可正常使用。
- 现有规则解析器处理固定格式的自然语言投递记录。
- 超出规则解析能力的请求返回可编辑表单，不猜测字段。

### 有模型模式

- 模型用于自由对话、岗位字段提取、面经结构化、复盘建议和自然语言查询规划。
- 模型输出必须通过 Pydantic 结构校验和业务规则校验。
- 模型不能直接访问文件、Notion 或系统命令，只能生成允许列表中的操作草稿。
- 远程模型调用前展示将发送的数据类别；用户可改用 Ollama 或取消。

## 配置与隐私

- 非敏感配置保存在 `%APPDATA%/JobHuntAgent/config.json`。
- API Key 和 Notion Token 存入 Windows Credential Manager。
- 日志默认脱敏，不记录面经正文、简历内容、完整岗位链接或密钥。
- 应用不提供自动投递、简历上传、浏览器登录接管或任意代码执行能力。
- GitHub Release 只包含代码、合成示例、测试和安装包。

## 错误处理

- Excel 被占用：保留草稿，提示关闭 WPS 后重试。
- Excel 写入验证失败：保留原文件和备份，不替换目标文件。
- Notion 不可用：本地保存成功，标记待同步并允许手动重试。
- 模型超时或输出不合法：回退到可编辑表单，不执行写入。
- 网络不可用：Excel 和本地面经继续工作，远程功能显示离线状态。
- 应用意外退出：未确认草稿不恢复为待执行操作，已确认操作依赖幂等 ID 防重。

## Windows 发布

- 后端使用 PyInstaller 打包。
- 前端构建产物嵌入应用资源目录。
- 使用 Windows 安装器生成单个安装 `.exe`，安装后创建桌面快捷方式。
- 应用本体采用目录式安装，避免单文件自解压带来的慢启动和杀毒软件误报。
- GitHub Actions 在 Windows 环境运行测试、构建前端、打包安装器并执行启动冒烟测试。

## 测试与验收

### 自动化测试

- Excel 读取、备份、原子替换、文件锁和样式保留测试。
- 本地 Markdown 与 Notion 存储契约测试。
- 各模型适配器的结构化输出契约测试。
- 操作草稿、确认令牌、幂等和取消流程测试。
- FastAPI 接口与 React 关键流程测试。
- 隐私扫描、日志脱敏和打包产物内容扫描。
- Windows 安装、首次启动、自动打开浏览器和卸载冒烟测试。

### 验收标准

- 未安装 Python、Node 或 Codex 的 Windows 电脑可以安装并启动应用。
- 未配置 Notion 和模型时可以完整管理 Excel 投递记录。
- 配置任一支持的模型后，对话可以生成可编辑的操作预览。
- 所有写操作均需要显式确认，重复确认不会产生重复记录。
- Excel、Notion或模型故障不会破坏现有数据。
- 发布包和 Git 历史不包含真实用户数据、私有链接或密钥。

## 非目标范围

- 多用户账户、云端托管和跨设备实时协作。
- 自动抓取招聘网站或自动提交职位申请。
- 将 Excel 与 SQLite 作为两个可写数据源。
- 在首个版本中内置或自动下载大型本地模型。
- 移动端原生应用。
